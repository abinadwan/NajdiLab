# Intentional Arabic content

English controls and documentation retain independent Arabic/RTL content in originals, corrections, manual examples, synthetic fixtures, linguistic vocabularies and stored compatibility values. Do not translate user data or rename machine-readable enums to localize the interface. Technical identifiers/code remain in their original script/direction.

Dataset-specific phase38/39 correction/review source can contain real private annotations; retention is not permission to publish. [Distribution policy](dataset-model-distribution-policy.md), [source provenance](source-provenance.md). Synthetic examples are independent fiction, not research review evidence. No linguistic word list is native-validated merely because it occurs in code; [review limitations](review-and-quality.md).

The old file/line inventory referred to removed source and is replaced by this content-based rule. Review each new Arabic occurrence by purpose and actual source, preserving text/Unicode/whitespace and privacy boundaries.
