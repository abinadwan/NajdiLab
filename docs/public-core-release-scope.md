# Core candidate scope

The separately generated Core is a local review/dataset tool: authenticated completed-turn ingestion, immutable originals/corrections, explicit flags, atomic stale-save protection, contextual privacy/holdout/mask checks, versions/manifests/diagnostics, selected JSONL retrieval and private coherent recovery. Its fictional workshop is opt-in, fresh-storage only. [Guide](public-core-user-guide.md).

It does not acquire/manage models, execute training, benchmark models, load private repair/evaluation evidence or deploy a runtime. Chat and external handoff are private-application features unless separately reviewed into its exact source mapping. Manual direct/preference/bulk/event/identity improvements require a new scoped design, never activation of deleted execution code.

The old phase backlog is replaced by this boundary. Prior candidate pass/failure counts stay in [verification evidence](verification-evidence.md), and current source changes require a newly built exact candidate. Engineering acceptance never closes [rights/publication](public-release-decision.md). A dataset download is not consent to redistribute it.
