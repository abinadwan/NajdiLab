# Source provenance investigation

Date: 2026-10-27. Baseline `15c751793a5470cbbfc5e83061afd604328a1ea7`; private development branch. This is an evidence inventory, **not proof of original authorship or redistribution permission**. [Rights matrix](dependency-licensing-matrix.md), [third-party attributions](third-party-attributions.md), [asset register](asset-provenance.md) and [release decision](public-release-decision.md) remain distinct references.

## Method and scope

Inventoried all 232 tracked baseline files, including 27 app modules, 42 scripts, 43 test/support files, 14 static assets, two config files, four startup migrations and four planned SQL/design files. Reviewed imports, license/copyright/copied/adapted/source-URL leads; module responsibilities; package manifests; frontend resources; available Git history (11 reachable commits including retained local work at this baseline); and existing rights reports. Exact personal commit identities remain private. No bundled font files or frontend package-manager dependency tree exists in tracked source.

The source reference scan found URLs for the project's own loopback APIs/tests, the official model repository and integration contracts. Copyright-like frontend matches concern the UI footer/year or selectable source labels, not proof of third-party code licensing. No explicit “copied/adapted from” header establishing a third-party source origin was identified in these scoped directories. Absence of a header does not establish originality. Earliest available commits already contain substantial code, so Git history cannot reconstruct pre-repository creation. No new source was removed or relicensed.

Distinctive-source external similarity searching was not warranted by a concrete copied-source lead in this scan and was not performed across the internet. Common standard-library/server/SQL/JS patterns and compatibility field names are not sufficient copying evidence. Unknown origins remain owner-confirmation items, not silently converted into verified original work. A later specific match must be compared at exact paths/revisions and with author/provenance context before assigning copied/adapted status.

## Owner follow-up and maintenance

Confirm original authorship, employer/contractor rights, contributor permission, AI-tool usage/terms, and any borrowed snippets/styles/icons/templates not recorded in Git. Identify exact upstream path/revision/license for each borrowed item. Preserve existing headers and attach applicable notices to the actual distribution; do not remove uncertain code as incidental cleanup. Future provenance changes must update this table, the asset register and distribution decision. The recommended source-only public snapshot remains blocked until protected research separation, history disposition and ownership/licensing gates close.
