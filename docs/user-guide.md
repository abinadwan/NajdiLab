# V2.3.0 user guide

Current Documentation — V2.3.0 development candidate

1. Launch your intended local checkout and check its health/database identity. In Settings, discover and explicitly connect an already managed local engine; select a model. No native application history is imported. Hermes collection stays blocked.
2. Create Chat with an admission budget and reply reserve. Ollama additionally requires explicit load approval; LM Studio uses an already-loaded model. Exact count plus reserve must fit. Overflow preserves/closes the old conversation and opens an empty collection-OFF one; the draft remains unsent.
3. Chat history is saved separately. Turn Collection ON only for new completed pairs you intend to review; it is OFF on creation/restart. Stop, failure, incomplete output or revoked consent produces no new review pair. Archive retains text and earlier exports while excluding linked reviews from future selection.
4. Inspect pending review context and original response. Save a separate complete correction or approve explicitly; inspect privacy/evaluation/exclusion flags and choose eligibility deliberately. Editing alone grants no rights or consent. Review/manual-data tools also accept independently authored local records.
5. Open Data workspace from the Dashboard or Data group. Its four stages are Data, Check and correct, Approve Gold, and Export. Add examples with the existing manual forms, edit with version history, duplicate, safely delete and choose records in the first stage. Next runs the existing privacy, eligibility, deduplication, split, structure and loss-mask checks for that choice. Edit or exclude a problem record and recheck in the same workspace. Approval requires an explicit confirmation. Gold freezes the chosen data. Export then offers compatible Unsloth profiles and separate raw files for each record type. Direct Language, DPO and evaluation records keep their own format. Filters retain hidden selections.
6. My versions shows files, Manifest/SHA256, readiness, direct entry to the Export stage and permanent deletion. Deletion requires a current ownership/dependency preview and exact typed version confirmation. Original records and history are retained. Legacy versions without managed-reference proof cannot be permanently deleted. Interrupted deletion remains listed for a fresh confirmed retry. The Wizard restores its stage, selected IDs and entry/edit drafts after refresh and application restart in the same browser origin. Old Advanced Mode preferences are ignored. The preserved interface is documented in the [developer archive](legacy/advanced-workspace/README.md).
7. Protect a private backup and rehearse restore into a separate empty directory. Archive is not erasure; historical exports/backups need a separate retention decision.
